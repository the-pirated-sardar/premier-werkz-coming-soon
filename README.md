# Premier Werkz: Coming Soon

A temporary, single-page "Website Coming Soon" site for **Premier Werkz Auto Salon** (Modesto, CA). It runs while the full website is built, then gets switched off. It's a standalone project with no shared code or infrastructure with the future site.

- **Repository:** https://github.com/the-pirated-sardar/premier-werkz-coming-soon
- **Preview:** https://the-pirated-sardar.github.io/premier-werkz-coming-soon/
- **Production domain (when connected):** https://premierwerkz.com (see [Connecting premierwerkz.com](#connecting-premierwerkzcom))

The page has three parts: a hero (logo, "Website Coming Soon", Audi S4 photograph), **Get in Touch** (a contact form that feeds a Google Form), and the business's contact details.

## How it works

Plain static HTML and CSS, generated by a small Node script with **no runtime dependencies**. The only JavaScript is a ~100-line inline script that improves the contact form.

```
site.config.js            all editable content (form, contact details, wording)
src/template.mjs          page markup (a function of the config)
src/styles.css            all styling (inlined into the page at build time)
src/form.js               contact form behaviour (inlined into the page at build time)
src/images.json           image sizes, written by `npm run images`
public/                   copied as-is: optimized images, fonts, icons
scripts/build.mjs         validates the config and writes dist/
scripts/form-fields.mjs   reads a Google Form's questions and prints config for it
scripts/google-form.mjs   shared Google Form helpers (used by the script above and the tests)
scripts/images.mjs        makes optimized images from the originals (run locally)
scripts/serve.mjs         local static server
scripts/screenshots.mjs   screenshots at all target screen sizes
tests/site.spec.js        Playwright tests (Chromium + WebKit, axe accessibility)
.github/workflows/deploy.yml   builds and publishes to GitHub Pages on every push to main
assets-source/            original photos and logos (git-ignored, kept on your Mac only)
```

**Layout.** On desktop the photo panel (logo, car, headline) sits on the left and the form plus contact details sit on the right, so everything fits on one screen at 1366×768 and up. On phones the sections stack in order: hero, form, contact.

**Paths.** All asset URLs are relative, so the same build works at `…github.io/premier-werkz-coming-soon/` and at the root of a custom domain. Unknown URLs (for example old `premierwerkz.com/work-request` links) forward to the homepage via `404.html`.

**Search engines.** The preview address (`*.github.io`) is always marked `noindex`. On a custom domain the page is indexable and gets a `sitemap.xml`, controlled by `seo.allowIndexing` in `site.config.js`.

## Updating content

Everything public (phone, email, address, social links, services line, headline and wording, the Google Form) lives in **`site.config.js`**, which is commented field by field.

**Easiest way (no tools needed):**

1. Open [`site.config.js` on GitHub](https://github.com/the-pirated-sardar/premier-werkz-coming-soon/blob/main/site.config.js) and click the ✏️ pencil icon.
2. Edit the values between the quotes. Leave a value as `''` to hide it (for example `availability: ''`).
3. Click **Commit changes…** then **Commit changes**.
4. The site redeploys automatically in about a minute ([watch it under Actions](https://github.com/the-pirated-sardar/premier-werkz-coming-soon/actions)).

If something in the file is invalid (say, a phone number with a missing digit or the wrong kind of form link), the deploy stops with a plain-English error in the Actions log and **the live site stays as it was**.

**Locally:** edit the file, run `npm run dev` to preview at http://localhost:4173/, then commit and push.

### Old addresses and typos go to the homepage

Every address that isn't a real file on the site forwards to the homepage: old premierwerkz.com pages such as `/work-request` or `/services/ceramic-coating`, deep links, and typos. There's nothing to configure.

How: GitHub Pages serves `404.html` for any unknown address, and the build makes that page forward instantly to the homepage (JavaScript, with a meta-refresh fallback for browsers without it). On the custom domain, GitHub first sends `www.premierwerkz.com/…` to `premierwerkz.com/…`, then the forward happens. Search engines see the old addresses as "not found" and drop them over time, which is fine for a temporary site.

## The contact form and Google Forms

The "Get in Touch" form is built into the page and styled to match it. When a visitor presses **Send message**, each answer is posted to the matching question of the Google Form set in `site.config.js`. Responses therefore appear in Google Forms as usual, including the linked Google Sheet and email notifications.

- **Validation** mirrors the Google Form (Name and Email required, Email must look like an email address), so Google never rejects a submission the page accepted.
- **Spam:** a hidden "honeypot" field silently drops submissions from simple bots.
- **Without JavaScript** the form still works: the browser posts straight to Google and shows Google's "response recorded" page.
- **If sending fails** (for example the visitor is offline), the answers are kept and the page offers a retry, the phone number, and a link to the Google Form itself.

**Limitation to know about.** Google doesn't let a web page read its reply to a form submission from another site, and the submission address (`…/formResponse`) is not an officially documented Google API. The page therefore treats "the request reached Google" as success. If the Google Form is unpublished, set to sign-in only, or its questions change, submissions could fail without the visitor seeing an error. The test suite checks the live form against `site.config.js` (`npm test`). Run it after changing the form, and check the response sheet occasionally.

### How fields map to the Google Form

Each Google Form question has an ID like `entry.205625071`. `site.config.js` lists the page's fields in order with the ID each one maps to:

```js
form: {
  url: 'https://docs.google.com/forms/d/e/<FORM-ID>/viewform',
  fields: [
    { entry: 'entry.205625071', label: 'Name', type: 'text', required: true, autocomplete: 'name' },
    { entry: 'entry.677626947', label: 'Email', type: 'email', required: true, autocomplete: 'email', half: true },
    { entry: 'entry.895985407', label: 'Phone', type: 'tel', autocomplete: 'tel', half: true },
    { entry: 'entry.160600044', label: 'How can we help?', type: 'textarea', placeholder: '…' },
  ],
},
```

### Switching to a different Google Form

1. In Google Forms, open the new form and click **Publish**. Under **Manage → General access** choose **Anyone with the link** (not "Restricted", which makes customers sign in to Google).
2. In **Settings → Responses**, make sure **Limit to 1 response** is off and **Collect email addresses** is *not* "Verified" (both force sign-in).
3. Copy the responder link: **Published → Copy responder link** (it looks like `https://docs.google.com/forms/d/e/…/viewform`).
4. Run:
   ```sh
   npm run form-fields -- 'https://docs.google.com/forms/d/e/<NEW-ID>/viewform'
   ```
   It prints a complete `form: { … }` block with the new question IDs. Paste it over the existing block in `site.config.js`. Re-add any `placeholder` text you want.
5. Run `npm test`. The "matches the live Google Form" test confirms every field exists and that required questions line up.
6. Commit and push, then send one test message through the live site and check it arrives.

**No tools?** You can find the IDs by hand: in Google Forms, **⋮ → Get pre-filled link**, type something in every question, click **Get link**, and paste the link somewhere. It contains `entry.<number>=<your text>` for each question.

Only **short answer** and **paragraph** questions are supported. A required multiple-choice, checkbox or dropdown question would make every submission fail; `npm run form-fields` warns about this.

### Moving to the Premier Werkz business-owned form

The current form belongs to a personal Google account. **Don't count on transferring ownership** of a Google Form between personal Gmail accounts. Instead, give the business its own form:

1. In the **current** form, click **Share** and add the business Google account as an **Editor**.
2. Signed in as the **business** account, open the form and choose **⋮ → Make a copy**. The copy belongs to the business account. (Or build a fresh form with the same four questions: Name *(required)*, Email *(required, Response validation → Text → Email address)*, Phone, How can we help? *(paragraph)*.)
3. In the business copy, set the confirmation message, then **Publish** with **Anyone with the link**. If the business account is Google Workspace, also turn off *"Restrict to users in [organization]"* under Settings → Responses.
4. **Responses → Link to Sheets** to create a response spreadsheet owned by the business, and **⋮ → Get email notifications for new responses**.
5. Follow [Switching to a different Google Form](#switching-to-a-different-google-form) above. A copy gets new question IDs, so step 4 there (`npm run form-fields`) is required.
6. Afterwards, download the old form's responses if you want to keep them, then remove the business account's access to the personal form (or delete it).

## Replacing images or the logo

The full-size originals live in `assets-source/` (git-ignored, so they never go into the public repository). Optimized versions are generated into `public/images/` and committed.

1. Put the new original(s) in `assets-source/photos/` or `assets-source/logos/`.
2. Point the script at them, near the top of `scripts/images.mjs`:
   ```js
   const HERO_SOURCE = 'assets-source/photos/DSC02753.jpg';
   const LOGO_SOURCE = 'assets-source/logos/gold ( print ready PDF file).pdf';
   ```
   The logo should be the transparent-background PDF (rasterized with `pdftocairo` from `brew install poppler`, or macOS `sips`).
3. Run `npm run images`. It creates AVIF/WebP/JPEG sizes for phones and desktops, the favicon, home-screen icon and the 1200×630 social-sharing image. All metadata (camera, Lightroom, location) is stripped.
4. Update `images.heroAlt` in `site.config.js` to describe the new photo.
5. Run `npm run screenshots` and look at `reports/screenshots/`. The desktop layout keeps the car centred at about 42% of the panel height and assumes, like DSC02753, that the subject sits near the middle of a portrait (2:3) frame. `DESKTOP_CROP` in `scripts/images.mjs` and the `object-position` rules in `src/styles.css` are the knobs if a new photo needs different framing.
6. Commit `public/`, `src/images.json` and any config changes.

## Local development and tests

Requires Node 20+ (`.nvmrc` pins 24).

```sh
npm install                              # dev tools only: sharp, Playwright, axe
npx playwright install chromium webkit   # first time only

npm run dev            # build + serve at http://localhost:4173/
npm test               # full test suite in Chromium and WebKit
npm run screenshots    # PNGs for 9 screen sizes into reports/screenshots/
npm run form-fields    # print the Google Form's question IDs as config
npm run images         # regenerate optimized images (needs assets-source/)
```

`npm test` builds and serves the site under `/premier-werkz-coming-soon/`, exactly how GitHub Pages serves the preview. It never sends real form responses (requests to Google are intercepted). It checks:

- no errors or broken images; unknown addresses forward to the homepage; no em or en dashes in the copy
- every contact link against `site.config.js`
- the form: wiring to the Google Form, required-field and email validation, the exact data sent to Google, the success and failure states, the spam trap, working without JavaScript, and that `site.config.js` matches the live Google Form
- no horizontal scrolling at 11 screen sizes; logo, headline, form and contact details all fit on screen at 1280 to 1920px desktops; 44px touch targets on phones
- keyboard use (skip link, completing the form without a mouse, visible focus), reduced motion, and an axe WCAG 2.2 AA scan including the form's error state

To run the same tests against the deployed site:

```sh
BASE_URL=https://the-pirated-sardar.github.io/premier-werkz-coming-soon/ npm test
```

## Deployment

Every push to `main` runs [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml): check out, `node scripts/build.mjs` (no `npm install` needed), publish `dist/` to GitHub Pages. Progress and logs are in the **[Actions tab](https://github.com/the-pirated-sardar/premier-werkz-coming-soon/actions)**. To redeploy without changes: Actions → *Deploy to GitHub Pages* → **Run workflow**.

Pages is configured with **Source: GitHub Actions** (Settings → Pages). The workflow learns the public URL (preview or custom domain) from GitHub, so canonical links and the social-sharing image always point at the right address.

## Connecting premierwerkz.com

The domain is registered with **GoDaddy** (nameservers `ns35/ns36.domaincontrol.com`). Its DNS still points at the old Webflow site:

| Host | Type | Current value |
|---|---|---|
| `@` | A | `75.2.70.75`, `99.83.190.102` (Webflow) |
| `www` | CNAME | `proxy-ssl.webflow.com` (Webflow) |

There are no MX (email) or TXT records, so nothing else is affected by the change.

**Before switching**, get the business details on the page confirmed by the owner. The domain makes the page public and indexable.

1. **Verify the domain with GitHub** (stops anyone else's Pages site from claiming it): GitHub → your avatar → **Settings → Pages → Add a domain** → `premierwerkz.com`. GitHub shows a `TXT` record (`_github-pages-challenge-the-pirated-sardar`). Add it in GoDaddy, then click **Verify**.
2. **In GoDaddy → My Products → premierwerkz.com → DNS**, replace the Webflow records:

   | Type | Name | Value | Action |
   |---|---|---|---|
   | A | `@` | `75.2.70.75` | delete |
   | A | `@` | `99.83.190.102` | delete |
   | A | `@` | `185.199.108.153` | add |
   | A | `@` | `185.199.109.153` | add |
   | A | `@` | `185.199.110.153` | add |
   | A | `@` | `185.199.111.153` | add |
   | AAAA | `@` | `2606:50c0:8000::153`, `…8001::153`, `…8002::153`, `…8003::153` | add (optional, IPv6) |
   | CNAME | `www` | `the-pirated-sardar.github.io` | change from `proxy-ssl.webflow.com` |

3. **In this repository → Settings → Pages → Custom domain**, enter `premierwerkz.com` and **Save**. (With GitHub Actions deployments no `CNAME` file is needed in the repo.)
4. Wait for the DNS check to pass (minutes to a few hours), then tick **Enforce HTTPS** once it's offered.
5. Re-run the deploy (Actions → *Deploy to GitHub Pages* → **Run workflow**) so canonical URLs, the sitemap and indexing switch to `https://premierwerkz.com/`.
6. Check `https://premierwerkz.com`, `https://www.premierwerkz.com` (should redirect), `https://www.premierwerkz.com/work-request` (should land on the homepage), and send a test message through the form.

GitHub's reference: [Managing a custom domain for your GitHub Pages site](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

## Troubleshooting

| Symptom | Fix |
|---|---|
| Messages sent from the site don't show up in Google Forms | Open the form's responder link in a private window. If it asks you to sign in, set **Published → Manage → General access → Anyone with the link**. If the form opens fine, the questions may have changed: run `npm run form-fields` and `npm test`. |
| `npm run form-fields` says the form requires sign-in | Same fix: **Anyone with the link**, *Limit to 1 response* off, email collection not "Verified". |
| Deploy failed with "site.config.js has problems" | Read the bullet list in the Actions log; it says exactly which value to fix. The live site is unaffected. |
| Deploy failed at "configure-pages" or "deploy" | Settings → Pages → Source must be **GitHub Actions**. |
| Custom domain shows a 404 or certificate warning | DNS hasn't propagated yet, or the custom domain field in Settings → Pages is empty. Check DNS with `dig premierwerkz.com +short` (it should list the four `185.199.x.153` addresses). |
| Images missing on the preview URL | Use relative paths (`images/…`, never `/images/…`) in `src/template.mjs`. The tests catch this. |
| Changes don't show up | Hard-refresh (⌘⇧R). GitHub Pages caches pages for up to 10 minutes. |

## Retiring this site

When the new website is ready:

1. **If the new site is hosted elsewhere:** in this repo, Settings → Pages → remove the custom domain, then point the GoDaddy DNS records at the new host. Afterwards unpublish: Settings → Pages → **Unpublish site** (or disable Pages).
2. **If the new site will also use GitHub Pages:** remove the custom domain here first, then add it to the new repository.
3. Archive this repository (Settings → **Archive this repository**) or delete it. Nothing else depends on it.
4. Decide what to do with the Google Form: keep it (the new site can post to the same form) or close it (*Responses → Accepting responses → off*).
