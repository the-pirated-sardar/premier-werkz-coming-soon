# Premier Werkz — Coming Soon

A temporary, single-page "Website Coming Soon" site for **Premier Werkz Auto Salon** (Modesto, CA). It runs while the full website is built, then gets switched off. It's a standalone project: no shared code or infrastructure with the future site.

- **Repository:** https://github.com/the-pirated-sardar/premier-werkz-coming-soon
- **Preview:** https://the-pirated-sardar.github.io/premier-werkz-coming-soon/
- **Production domain (when connected):** https://premierwerkz.com — see [Connecting premierwerkz.com](#connecting-premierwerkzcom)

The page has three parts: a hero (logo, "Website Coming Soon", Audi S4 photograph), **Get in Touch** (an embedded Google Form), and the business's contact details.

## How it works

Plain static HTML and CSS, generated by a ~200-line Node script with **no runtime dependencies and no JavaScript on the page**.

```
site.config.js          ← all editable content (form, contact details, wording)
src/template.mjs        ← page markup (a function of the config)
src/styles.css          ← all styling (inlined into the page at build time)
src/images.json         ← image sizes, written by `npm run images`
public/                 ← copied as-is: optimized images, fonts, icons
scripts/build.mjs       ← validates the config and writes dist/
scripts/images.mjs      ← makes optimized images from the originals (run locally)
scripts/measure-form.mjs← measures the Google Form's height
scripts/serve.mjs       ← local static server
scripts/screenshots.mjs ← screenshots at all target screen sizes
tests/site.spec.js      ← Playwright tests (Chromium + WebKit, axe accessibility)
.github/workflows/deploy.yml ← builds and publishes to GitHub Pages on every push to main
assets-source/          ← original photos and logos (git-ignored — kept on your Mac only)
```

**Layout.** On desktop the photo panel holds still on the left (logo top-left, contact details top-right, headline bottom-left) while the form column on the right scrolls, so everything is visible at once on typical laptop and desktop screens. On phones the sections stack in order: hero → form → contact.

**Paths.** All asset URLs are relative, so the same build works at `…github.io/premier-werkz-coming-soon/` and at the root of a custom domain. Unknown URLs (for example old `premierwerkz.com/services/…` links) show this page via `404.html`.

**Search engines.** The preview address (`*.github.io`) is always marked `noindex`. On a custom domain the page is indexable and gets a `sitemap.xml` — controlled by `seo.allowIndexing` in `site.config.js`.

## Updating content

Everything public — phone, email, address, social links, services line, headline and wording, the Google Form — lives in **`site.config.js`**, which is commented field by field.

**Easiest way (no tools needed):**

1. Open [`site.config.js` on GitHub](https://github.com/the-pirated-sardar/premier-werkz-coming-soon/blob/main/site.config.js) and click the ✏️ pencil icon.
2. Edit the values between the quotes. Leave a value as `''` to hide it (for example `availability: ''`).
3. Click **Commit changes…** → **Commit changes**.
4. The site redeploys automatically in about a minute ([watch it under Actions](https://github.com/the-pirated-sardar/premier-werkz-coming-soon/actions)).

If something in the file is invalid (say, a phone number with a missing digit or the wrong kind of form link), the deploy stops with a plain-English error in the Actions log and **the live site stays as it was**.

**Locally:** edit the file, run `npm run dev` to preview at http://localhost:4173/, then commit and push.

## Changing the Google Form

The form is embedded with Google's official `?embedded=true` iframe. Swapping it only requires changing **one line** in `site.config.js`.

### Swap in a different form

1. In Google Forms, open the new form → **Publish** (top right). Under **Manage → General access**, choose **Anyone with the link** — *not* "Restricted", which forces customers to sign in to Google.
2. In **Settings → Responses**, make sure **Limit to 1 response** is off and **Collect email addresses** is *not* "Verified" (both force sign-in).
3. Copy the link: **⋮ → Embed HTML**, then copy just the `src="…"` address (or use **Published → Copy responder link**). Either form works:
   `https://docs.google.com/forms/d/e/<ID>/viewform` or `…/viewform?embedded=true`.
   *Don't* use the editor link (`…/forms/d/<ID>/edit`) or a `forms.gle` short link — the build will refuse them with an explanation.
4. Paste it into `site.config.js`:
   ```js
   form: {
     url: 'https://docs.google.com/forms/d/e/<NEW-ID>/viewform?embedded=true',
   ```
5. Commit. Both the embedded form and the "Open it in a new tab" fallback switch over.
6. **Check it in a private/incognito window** (so you're not signed in to Google): the form's questions should appear on the site, not a sign-in page.

### If the new form has different questions

The page reserves exactly enough height for the form so its Submit button is never cut off. Google doesn't let the page detect the form's height, so it's set in `site.config.js` (`form.height`). A form with the same four questions renders at the same height — nothing to do. If you add or remove questions, re-measure:

```sh
npm run measure-form    # prints suggested `height: { desktop, mobile }` values
```

Paste the suggested numbers into `site.config.js` and commit. (The tests also check that Submit fits.)

### Moving to the Premier Werkz business-owned form

The current form belongs to a personal Google account. **Don't count on transferring ownership** of a Google Form between personal Gmail accounts — instead, give the business its own form:

1. In the **current** form, click **Share** (or ⋮ → *Add collaborators*) and add the business Google account as an **Editor**.
2. Signed in as the **business** account, open the form and choose **⋮ → Make a copy**. The copy belongs to the business account. (Or build a fresh form with the same four questions: Name *(required)*, Email *(required, Response validation → Text → Email address)*, Phone, How can we help? *(paragraph)*.)
3. In the business copy: re-apply the theme if needed (**Color** `#1A1B20`, lightest grey background), set the confirmation message, then **Publish** with **Anyone with the link**. If the business account is Google Workspace, also turn off *"Restrict to users in [organization]"* under Settings → Responses.
4. **Responses → Link to Sheets** to create a response spreadsheet owned by the business, and **⋮ → Get email notifications for new responses**.
5. Swap the link in `site.config.js` (steps above) and verify in a private window.
6. Send one test response through the live site and confirm it arrives in the business's sheet/inbox.
7. Afterwards: download the old form's responses if you want to keep them, then remove the business account's access to the personal form (or delete the old form).

## Replacing images or the logo

The full-size originals live in `assets-source/` (git-ignored, so they never go into the public repository). Optimized versions are generated into `public/images/` and committed.

1. Put the new original(s) in `assets-source/photos/` or `assets-source/logos/`.
2. Point the script at them — near the top of `scripts/images.mjs`:
   ```js
   const HERO_SOURCE = 'assets-source/photos/DSC02753.jpg';
   const LOGO_SOURCE = 'assets-source/logos/gold ( print ready PDF file).pdf';
   ```
   The logo should be the transparent-background PDF (rasterized with `pdftocairo` from `brew install poppler`, or macOS `sips`).
3. Run `npm run images`. It creates AVIF/WebP/JPEG sizes for phones and desktops, the favicon, home-screen icon and the 1200×630 social-sharing image. All metadata (camera, Lightroom, location) is stripped.
4. Update `images.heroAlt` in `site.config.js` to describe the new photo.
5. Run `npm run screenshots` and look at `reports/screenshots/`. The desktop layout keeps the car centred at ~42% of the panel height and assumes, like DSC02753, that the subject sits near the middle of a portrait (2:3) frame — `DESKTOP_CROP` in `scripts/images.mjs` and the `object-position` rules in `src/styles.css` are the knobs if a new photo needs different framing.
6. Commit `public/`, `src/images.json` and any config changes.

## Local development and tests

Requires Node 20+ (`.nvmrc` pins 24).

```sh
npm install                       # dev tools only: sharp, Playwright, axe
npx playwright install chromium webkit   # first time only

npm run dev            # build + serve at http://localhost:4173/
npm test               # full test suite in Chromium and WebKit
npm run screenshots    # PNGs for 9 screen sizes → reports/screenshots/
npm run measure-form   # Google Form heights → suggested config values
npm run images         # regenerate optimized images (needs assets-source/)
```

`npm test` builds and serves the site under `/premier-werkz-coming-soon/` — exactly how GitHub Pages serves the preview — and checks: no errors or broken images, the 404 page, every contact link against `site.config.js`, the form wiring, that the live Google Form is publicly reachable and its Submit button fits, no horizontal scrolling at 11 screen sizes, that logo/headline/form/contact details all fit on screen at 1280–1920px desktops, 44px touch targets on phones, keyboard navigation, reduced motion, and an axe WCAG 2.2 AA scan.

## Deployment

Every push to `main` runs [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml): check out → `node scripts/build.mjs` (no `npm install` needed) → publish `dist/` to GitHub Pages. Progress and logs: **[Actions tab](https://github.com/the-pirated-sardar/premier-werkz-coming-soon/actions)**. To redeploy without changes: Actions → *Deploy to GitHub Pages* → **Run workflow**.

Pages is configured with **Source: GitHub Actions** (Settings → Pages). The workflow learns the public URL (preview or custom domain) from GitHub, so canonical links and the social-sharing image always point at the right address.

## Connecting premierwerkz.com

The domain is registered with **GoDaddy** (nameservers `ns35/ns36.domaincontrol.com`). Today its DNS still points at the old Webflow site:

| Host | Type | Current value |
|---|---|---|
| `@` | A | `75.2.70.75`, `99.83.190.102` (Webflow) |
| `www` | CNAME | `proxy-ssl.webflow.com` (Webflow) |

There are no MX (email) or TXT records, so nothing else is affected by the change.

**Before switching**, get the business details on the page confirmed by the owner — the domain makes the page public and indexable.

1. **Verify the domain with GitHub** (prevents anyone else's Pages site from claiming it): GitHub → your avatar → **Settings → Pages → Add a domain** → `premierwerkz.com`. GitHub shows a `TXT` record (`_github-pages-challenge-the-pirated-sardar`) — add it in GoDaddy, then click **Verify**.
2. **In GoDaddy → My Products → premierwerkz.com → DNS**, replace the Webflow records:

   | Type | Name | Value | Action |
   |---|---|---|---|
   | A | `@` | `75.2.70.75` | delete |
   | A | `@` | `99.83.190.102` | delete |
   | A | `@` | `185.199.108.153` | add |
   | A | `@` | `185.199.109.153` | add |
   | A | `@` | `185.199.110.153` | add |
   | A | `@` | `185.199.111.153` | add |
   | AAAA | `@` | `2606:50c0:8000::153`, `…8001::153`, `…8002::153`, `…8003::153` | add (optional, IPv6) |
   | CNAME | `www` | `the-pirated-sardar.github.io` | change from `proxy-ssl.webflow.com` |

3. **In this repository → Settings → Pages → Custom domain**, enter `premierwerkz.com` and **Save**. (With GitHub Actions deployments no `CNAME` file is needed in the repo.)
4. Wait for the DNS check to pass (minutes to a few hours), then tick **Enforce HTTPS** once it's offered.
5. Re-run the deploy (Actions → *Deploy to GitHub Pages* → **Run workflow**) so canonical URLs, the sitemap and indexing switch to `https://premierwerkz.com/`.
6. Check `https://premierwerkz.com`, `https://www.premierwerkz.com` (should redirect) and the form in a private window.

GitHub's reference: [Managing a custom domain for your GitHub Pages site](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

## Troubleshooting

| Symptom | Fix |
|---|---|
| Form shows **"Sign in to your Google Account"** | The form isn't public. Google Forms → **Published → Manage → General access → Anyone with the link**; also turn off *Limit to 1 response* and don't use *Verified* email collection. |
| Form area is blank / **"refused to connect"** | The link in `site.config.js` isn't a published responder link, or the form was deleted/unpublished. Re-copy it from **⋮ → Embed HTML**. |
| Submit button cut off / form has its own scrollbar | Questions changed — run `npm run measure-form` and update `form.height`. |
| Deploy failed with "site.config.js has problems" | Read the bullet list in the Actions log; it says exactly which value to fix. The live site is unaffected. |
| Deploy failed at "configure-pages" or "deploy" | Settings → Pages → Source must be **GitHub Actions**. |
| Custom domain shows a 404 or certificate warning | DNS hasn't propagated yet, or the custom domain field in Settings → Pages is empty. Check DNS with `dig premierwerkz.com +short` (should list the four `185.199.x.153` addresses). |
| Images missing on the preview URL | Use relative paths (`images/…`, never `/images/…`) in `src/template.mjs`. The tests catch this. |
| Changes don't show up | Hard-refresh (⌘⇧R). GitHub Pages caches pages for up to 10 minutes. |

## Retiring this site

When the new website is ready:

1. **If the new site is hosted elsewhere:** in this repo, Settings → Pages → remove the custom domain, then point the GoDaddy DNS records at the new host. Afterwards unpublish: Settings → Pages → **Unpublish site** (or disable Pages).
2. **If the new site will also use GitHub Pages:** remove the custom domain here first, then add it to the new repository.
3. Archive this repository (Settings → **Archive this repository**) or delete it. Nothing else depends on it.
4. Decide what to do with the Google Form: keep it (the new site can embed the same form) or close it (*Responses → Accepting responses → off*).
